# Arquitectura propuesta

- `src/domain/` TypeScript estricto. Entidades, reglas puras y contratos de persistencia. Sin dependencias del DOM, React, IndexedDB ni Chrome.
- `src/content/` adaptador DOM aislado. Captura selección, proyecta texto a offsets, recupera rangos, pinta y desplaza. Solo recibe el corpus del proyecto activo para su URL.
- `src/background/` service worker MV3. Valida mensajes y remitentes, ejecuta casos de uso y abre Dexie bajo el origen de extensión. El estado durable reside en IndexedDB. Las solicitudes llevan ID de operación cuando el reintento pueda duplicar una mutación. Las respuestas de éxito se envían tras el commit. Un ACK perdido debe poder reintentarse sin duplicar datos.
- `src/storage/` repositorio Dexie con tablas indexadas y escrituras transaccionales. `src/panel/` React para el Side Panel. El panel intercambia DTO JSON con el worker y muestra estados de carga, guardado y error. No accede directamente al DOM web.
- Vite empaquetará panel HTML y entradas de extensión. El worker puede ser módulo MV3. El content script debe empaquetarse como script autónomo sin imports runtime remotos. T001 incorpora los puntos de entrada, manifiesto y verificación del contenido de dist.

## Permisos y ciclo de vida

Permisos base propuestos `sidePanel` y `scripting`. Declarar hosts opcionales HTTP(S) y solicitar el patrón de un sitio desde una acción explícita del usuario. Chrome no distingue puertos en patrones de host. Limitar el uso adicionalmente a orígenes registrados. Tras conceder, registrar dinámicamente el content script para el sitio con persistencia entre sesiones e inyectarlo en la pestaña actual de forma idempotente. Revocación retira registros, limpia pintura en sesiones activas cuando sea posible y bloquea nuevas lecturas. Reconciliar registros y permisos al inicio. Restringir a frame principal y validar tabId, documentId y URL de remitentes. No declarar permisos de historial, cookies ni acceso obligatorio a todos los sitios. Para navegación por evidencia, coordinar la pestaña destino y su documento nuevo hasta que el content script anuncie disponibilidad. Un timeout devuelve un estado recuperable. [Side Panel](https://developer.chrome.com/docs/extensions/reference/api/sidePanel) · [Scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting) · [Permisos](https://developer.chrome.com/docs/extensions/reference/api/permissions)

En T002, comprobar el acceso instala la captura en el documento autorizado. El content script conserva una instantánea de la selección al pasar el foco al panel y solo responde a la página del panel de la extensión. El panel consulta la pestaña activa y pide la instantánea al documento exacto mediante mensajería de Chrome. La captura se limita a 1 000 000 unidades UTF-16 de texto indexable y 16 384 por cita. El identificador de documento, la URL y la revisión del índice acompañan cada captura. Si cambian antes de guardar, volver a seleccionar. Validar forma, tamaño, clase de mensaje y procedencia en los límites. No usar puentes con código de página. Renderizar texto como texto y limitar CSS dinámico a colores hex y nombres generados por extensión. No incluir analítica, fetch de datos de investigación, scripts remotos ni eval. IndexedDB es local al perfil y el archivo exportado es texto legible.

## Anclaje y pintura

1. Proyectar el cuerpo del documento a un flujo de texto y mapa bidireccional de puntos DOM. El perfil v1 concatena el texto de nodos admitidos en orden DOM sin colapsar espacios. Excluir script, style, template, noscript, subárboles hidden y editables. Rechazar rangos que crucen subárboles excluidos con texto. Probar nodos inline, bloques adyacentes, emoji y cambios del árbol. Versionar el perfil con los selectores.
2. Verificar posición contra la cita exacta. Buscar las ocurrencias exactas para comprobar unicidad. Con varias ocurrencias, elegir solo si exactamente una coincide con todo el contexto disponible registrado y existe contexto no vacío. Usar posición para recuperar rápido el rango candidato, sin desempatar duplicados por distancia. Sin candidato confiable, mantener la cita sin pintura.
3. Observar cambios de texto, estructura y atributos que alteren las exclusiones. Invalidar el mapa, agrupar actualizaciones y reconstruir solo si hay evidencia o captura pendiente. Verificar URL también en cambios de ruta SPA, con sondeo acotado mientras haya evidencias o una sesión de captura, además de eventos de navegación accesibles. Limpiar pintura al cambiar de fuente, proyecto o permiso.
4. Segmentar por los límites de anotaciones resueltas. En cada tramo, priorizar el código filtrado si está presente, luego menor longitud de anotación, luego orden por ID de anotación y código. Mostrar todos los códigos en el panel. Un fragmento sin códigos conserva nota y cita y puede seleccionarse desde el panel. Registrar rangos por color en CSS.highlights con nombres propios y retirar solo los registros propios. Pintar sin envolver texto. Si CSS.highlights no está disponible, mostrar un estado de compatibilidad.

## Justificación del stack

TypeScript estricto para DTO y reglas, React para el panel con estado interactivo, Vite para empaquetado local y Dexie para índices y transacciones IndexedDB. MV3 y Side Panel son interfaces de destino. Chrome 123 es el piso propuesto y Brave estable requiere comprobación manual. Vitest para lógica y almacenamiento, Playwright Test para flujos reales, ESLint para reglas y Prettier para estilo. El análisis y la decisión del motor se conservan en [reference-analysis.md](reference-analysis.md).
